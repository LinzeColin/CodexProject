# Product

## Register

product

## Users

WDA is used by the local owner/operator on the new computer as a private WeChat data analysis control plane. The user is usually trying to answer work, relationship, risk, opportunity, handoff, and personal-behavior questions from a local Data Core without running terminal commands or moving files manually.

## Product Purpose

WDA v0.2-R3 turns the proven v0.2-R2 local Data Core into a usable desktop-style product surface: a double-click local entry, a FastAPI local service, a Chinese dashboard, a manual update action, a launchd scheduler template, and local full-sensitive Chinese reports. Success means the owner can open the app, see freshness and decision-oriented summaries, trigger an update, inspect failures, and navigate to evidence-backed local reports while raw/private data stays outside Git.

## Brand Personality

Calm, operational, evidence-first. The interface should feel like a serious local command center for repeated daily use: direct Chinese copy, dense but scannable layouts, restrained color, visible system state, and no decorative marketing treatment.

## Anti-references

Do not make WDA look like a landing page, raw Markdown directory, CSV browser, technical validation dashboard, chat toy, or cloud SaaS marketing site. Avoid oversized hero sections, ornamental gradients, hidden raw-data claims, vague AI summaries, and pages that lead with row counts instead of decisions.

## Design Principles

1. Put decisions before mechanics: homepage content starts with actions, risks, opportunities, and freshness, not file paths or schema trivia.
2. Keep trust visible: every report entry should expose evidence links, run status, warnings, and data boundaries.
3. Optimize for one local operator: double-click entry, predictable navigation, no manual command chain for normal use.
4. Respect privacy by architecture: full-sensitive outputs stay under `WDA_MetaData`; repo-safe files contain only code, counts, sanitized examples, and docs.
5. Use restrained product UI: familiar controls, clear states, readable Chinese typography, no decorative complexity.

## Accessibility & Inclusion

Target readable product UI with WCAG AA contrast for text, keyboard-reachable controls, visible focus states, semantic navigation, reduced-motion-safe transitions, and Chinese-first labels. Motion should communicate state only.
